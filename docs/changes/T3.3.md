### Added — НОВАЯ МОДЕЛЬ tz-1.0.0 — публичный каталог: список с фильтрами, карточка с провенансом, сравнение, иерархия (числа не меняются)

Три гостевые страницы каталога (ТЗ §2.1.1, §3.1.2, §3.3.1, §3.3.4, §3.3.7). Страницы читают
данные через `lib/catalog/queries` (`getCatalogList`, `getCatalogProduct`, `getCatalogProducts`,
`latestDataRelease`) и три лёгких запроса справочников из `app/catalog/_lib/data.ts`. Каждая
страница начинается с `await connection()`. Значения searchParams берутся только строками
(`typeof === "string"`), неизвестные значения фильтров игнорируются.
**МЕНЯЕТ ЧИСЛА: нет.** Каталог только показывает вынесенные колонки и характеристики, ничего
не пересчитывает. На каждой странице одно h1. Строк, которые e2e v1 ищут строго, в
разметке нет, и тест это проверяет.

- **`/catalog` — список** (h1 «Каталог роботизированных решений»).
  - Фильтры — GET-форма, поэтому работает без JavaScript, а выборка сохраняется в адресе:
    «Поиск», «Тип объекта», «Процесс» (сгруппирован по объектам), «Тип решения», «Статус»
    (в эксплуатации / пилот / НИОКР), «Глубина описания», «Только с подтверждёнными данными»,
    «Есть модель RaaS», «Сортировка» (название, цена, производительность, полнота).
  - При сортировке по производительности без выбранного процесса показывается подсказка:
    единицы у разных процессов разные.
  - Колонки таблицы: решение и производитель, тип решения и процессы, чип статуса, цена
    (`formatRub` или «нет данных»), ставка RaaS, производительность с единицей, полоса полноты
    данных. Чипы: «требует проверки», «только идентификация», «не участвует в подборе».
  - Под таблицей сноска. Цена и ставка RaaS — типичное значение диапазона из источника.
    Производительность — паспортная норма на одного робота, станцию или канал. В расчёте парка
    мобильных роботов норма сравнивается с циклом по планировке объекта, и берётся меньшее.
    Диапазоны, оговорки «от/до» и то, идёт ли норма в расчёт, показаны в карточке. Число в
    колонке не выдаётся за число расчёта: на демо-складе цикл H1500 по планировке меньше
    нормы 90 паллет/ч, и парк считается по циклу (значения печатает
    `scripts/print-demo-numbers.ts`).
  - Страницы по 50 строк, навигация по страницам с сохранением фильтров.
  - Первая колонка — флажки `name="ids"`. До 4 решений → «Сравнить выбранные» →
    `/catalog/compare?ids=a,b`. Пятый флажок снимается с сообщением. Без JavaScript форма
    отправляет `ids=a&ids=b`, и страница сравнения понимает обе формы.
  - Дерево иерархии «отрасль → тип объекта → процесс → тип решения» с числом продуктов на
    каждом звене (свёрнуто, чтобы на экране 1366×768 таблица оставалась на первом экране).
    Звенья дерева — ссылки на список с теми же фильтрами, числа считаются по тем же правилам.
    Отдельной строкой указано число продуктов без привязки к типу объекта (на текущих данных
    их 142 из 188).
  - Строка выпуска данных: версия и дата синхронизации, общее число продуктов.
- **`/catalog/[slug]` — карточка** (h1 = название продукта).
  - «Хлебные крошки»: Отрасль → Тип объекта → Процесс → Тип решения → Продукт. Если продукт
    относится к нескольким объектам или процессам, строится несколько путей (у MARK 2 SE их
    три). Отсутствующее звено подписано «не указан».
  - Чипы: статус, глубина описания, «требует проверки», «не участвует в подборе», «в архиве».
    Описание продукта (≤ 200 знаков) идёт с бейджем «Организатор · каталог организатора › id …».
  - Блок «Требует проверки перед использованием в расчёте» перечисляет причины. Они считаются
    по тем же правилам, что колонка `needsVerification` (`verificationReasons` из
    `lib/catalog/promote`), плюс расхождения источников.
  - Ключевые значения — цена, ставка RaaS, производительность, грузоподъёмность, скорость —
    показаны с бейджами источника. Под производительностью — пояснение по правилам движка
    (`normThroughput` и `throughputFor` из `lib/tz/econ/fleet`, `calcSupported` процесса):
    - норма проходит: «норма для расчёта парка: 90 паллет/ч на робота; в расчёте берётся
      меньшее из нормы и цикла по планировке объекта». У немобильной станции вместо второй
      части: «цикл по планировке для него не считается, парк считается по норме»;
    - норма не проходит: «в расчёт парка не идёт: …» с причиной движка. Например, у
      Stelkon Pallet Shuttle значение на канал, а не на робота или станцию. Другие причины:
      указан только предел «до», значение на весь парк, экономика процессов продукта в
      прототипе не рассчитывается (уборка, штучный отбор);
    - продукт вне подбора — пояснения нет, его цифры в расчёт не попадают.
  - Шесть групп ТЗ §3.3.4 с заголовками h2 из словаря `CHAR_GROUP_LABELS` и счётчиком
    «заполнено X из Y обязательных». Названия групп те же, что в отчёте и админке, поэтому
    группа инфраструктуры называется «Требования к инфраструктуре», а не коротким
    «Инфраструктура» из плана задачи. В каждой строке: значение с единицей, «как в источнике»
    (дословная цитата), `SourceBadge` (ссылка, место в источнике, дата, основание), «проверено
    ДД.ММ.ГГГГ», достоверность и подтверждение ✓/—.
  - Альтернативные значения раскрываются в `<details>`: «⚠ есть расхождения (N)», если
    источники расходятся сверх допуска, иначе «другие источники (N)».
  - Обязательные характеристики, которых нет у продукта, показаны строками «нет данных»: видно,
    из чего складывается полнота.
  - Сводка «Качество данных»: полнота (заполнено X из 31), доля подтверждённых, число
    расхождений, глубина описания, участие в подборе, происхождение карточки, версия данных и
    дата обновления. Пояснение к глубине описания говорит только о том, насколько заполнена
    карточка и откуда данные. Об участии в подборе оно ничего не утверждает.
  - Участие в подборе считает одна функция `selectionParticipation` (product-card.tsx). Условия
    те же, что у `getCalcProducts`. Ответ «нет» с причиной получают:
    - продукт в архиве;
    - продукт уровня «только идентификация»;
    - исключённый продукт (причина исключения);
    - продукт без привязки к процессам модели («не привязан ни к одному процессу модели»).
      На текущих данных это 10 обогащённых неисключённых продуктов, например amt-6x6.

    Остальные получают «да — входит в подбор для процесса «…»; подходит ли продукт объекту,
    решает подбор по параметрам объекта». Эту же функцию используют сводка качества, строка
    сравнения «Участвует в подборе», ссылки в демо и пояснение к производительности.
  - Ссылка «Открыть в демо-расчёте склада» ведёт на `/demo?facility=warehouse`. Для
    аэропорта и больницы — «Открыть демо для объекта «…»». У продукта, который в подбор не
    входит, вместо ссылки написана причина: «В подбор демо-расчёта продукт не входит: …». Ещё
    есть ссылка «Сравнить с другими решениями».
  - Несуществующий slug отдаёт 404. Архивный продукт открывается с баннером: на него могут
    ссылаться проекты.
- **`/catalog/compare?ids=`** — до 4 продуктов бок о бок.
  - Блок «Кратко»: цена, RaaS, производительность, полнота, доля подтверждённых, требует ли
    проверки, участвует ли в подборе (`selectionParticipation`, причина при «нет»).
  - Архивный продукт, открытый по старой ссылке, помечен в заголовке столбца чипом «в архиве»,
    как в карточке. В строке «Участвует в подборе» у него «нет: в архиве».
  - Строки по шести группам: все обязательные характеристики и все, что заполнены хотя бы у
    одного продукта. В ячейках — бейдж источника, ✓/— и ⚠ при расхождении.
  - У каждого продукта ссылка «Убрать из сравнения».
  - Форма «Добавить к сравнению» предлагает продукты тех же процессов. Она перенаправляет на
    канонический адрес `ids=a,b,c`.
  - Показаны предупреждения о продуктах сверх четырёх и о ненайденных slug'ах.
  - Лучшее значение в строке намеренно не выделяется: значения из разных источников с разной
    степенью подтверждения.
- **Компоненты `components/catalog/*`**: `filters.tsx`, `catalog-table.tsx`,
  `compare-form.tsx` (клиентский, единственный), `characteristic-row.tsx`,
  `group-section.tsx`, `breadcrumb.tsx`, `hierarchy.tsx`, `compare-table.tsx`,
  `product-card.tsx`, `pagination.tsx`, `chips.tsx`, а также модули без React:
  `search-params.ts`, `labels.ts`, `options.ts`.
- **Тест** `components/catalog/catalog.test.ts` (unit, 23 теста). Покрывает:
  - разбор адреса и обратную сборку ссылок, обе формы `ids` и предел 4;
  - числа дерева иерархии и пути «хлебных крошек»;
  - полноту групп и причины «требует проверки»;
  - пояснение к производительности: норма против цикла, станция, значение на канал, процесс
    без экономики, продукт вне подбора;
  - участие в подборе: обогащённый продукт без процессов, исключённый, архивный, уровня
    идентификации. Проверяется, что сводка качества и ссылки в демо не обещают участие, а
    сравнение помечает архивный продукт;
  - отрисовку таблицы, групп, крошек, сравнения и формы сравнения, в том числе без
    JavaScript;
  - отсутствие h1 и запрещённых подписей в разметке компонентов.
