### Added — сборщики выгрузок проекта: строки отчёта, CSV и XLSX из 13 листов с формулами (числа не меняются)

Модуль `lib/report/tz` собирает отчёт из сохранённых результатов проекта (`ProjectResults`) и
ничего не пересчитывает. Горизонт H и ставку дисконтирования он берёт из сохранённых параметров и
нормативов теми же функциями движка, что и расчёт (`horizonOf`, `normsForSpec`). Выход движка не
меняется, флаг «МЕНЯЕТ ЧИСЛА» не нужен. Требования ТЗ: §3.7.2, §3.7.3, §3.5.8.

- **`rows.ts`: строки отчёта.** Модуль без внешних зависимостей, работает и на сервере, и в браузере.
  Числа форматирует только `lib/format/rub` и `lib/format/plural`.
  - `scenarioTableRows(results)` строит таблицу сценариев в порядке экрана T2.6. Строки: «Состав
    оборудования», «CAPEX», «OPEX в год», «ФОТ процесса», «Годовой эффект», «Окупаемость
    (простая)», «Интерпретация», «ROI по ТЗ», «ROI чистый», «NPV», «Дисконтированная окупаемость»,
    «TCO за {T} лет», «Изменение TCO к «Как есть»», «Имитация», «Риски», «Вывод».
    - Каждая строка отдаёт текст ячеек `cells` для печати и числа `values` для XLSX и CSV.
    - Если сценарий не рассчитан, в строке состава стоит «Не рассчитан: {причина}», а в числовых
      строках «—». Ноль вместо отказа не выводится.
    - ROI услуги (RaaS) сопровождает примечание «ROI неинформативен при малом CAPEX — сравнивайте
      NPV и TCO».
    - Рекомендуемый сценарий помечен ★. Сценарий с решением, добавленным вручную, помечен ⚠ в
      заголовке.
  - `paramsRows(results, defs)` строит таблицу параметров объекта. Для каждого параметра она
    показывает:
    - значение, с которым выполнен расчёт;
    - значение по умолчанию и диапазон организатора;
    - источник: происхождение значения по умолчанию или «Задано вами»;
    - замечания проверки и пометку ⚠, если значение вне диапазона организатора.
  - `cashflowRows(result)` строит денежный поток по годам t = 0…T.
  - `sourcesRows(results)` перечисляет источники характеристик продуктов из снимка проекта: ссылку,
    дату и признак подтверждения.
  - `changeRows(changes)` строит журнал корректировок. Поле `param:…`, `item:…:quantity`,
    `norm:…` или `scenario:add` получает подпись по-русски, дата выводится по московскому времени.
- **`tables.ts`: остальные разделы отчёта.** Модуль тоже без внешних зависимостей. В нём строки
  для подбора, сравнения решений, состава оборудования, статей CAPEX и OPEX, чувствительности,
  нормативов, имитации (через `simSummaryRows` из `lib/sim/export-rows`), рисков, формул и
  ограничений модели. Их используют книга XLSX и печатный отчёт T3.2.
- **`csv.ts`: `projectCsv(results, { projectName })`.**
  - Формат: BOM, разделитель «;», десятичная запятая, CRLF, защита от формул. Имя «=cmd»
    превращается в «'=cmd».
  - Порядок: шапка (объект, дата, версии), сравнение сценариев с выводом, денежный поток каждого
    сценария, последней строкой оговорка «Результат является предварительной оценкой…».
  - Числа пишутся числами, единицы стоят в подписях. Модуль не зависит от Node, поэтому гостевой
    расчёт собирает CSV прямо в браузере.
- **`xlsx.ts`: `buildProjectXlsx({ projectName, results, defs, changes })` возвращает `Uint8Array`.**
  Работает только на сервере, через exceljs.
  - Листы, 13 шт.: «Сводка», «Параметры объекта», «Подбор», «Состав оборудования», «CAPEX»,
    «OPEX», «Денежный поток», «Чувствительность», «Имитация», «Нормативы и допущения»,
    «Источники», «Журнал корректировок», «О расчёте».
  - Итоговые показатели записаны живыми формулами. В каждой формуле сохранён результат расчёта,
    а Excel пересчитывает формулы при открытии (`fullCalcOnLoad`):
    - итоги CAPEX и OPEX: `SUM` по статьям;
    - эффект и поток каждого года;
    - окупаемость: `IF(E>0, CAPEX/E, …)`;
    - ROI по ТЗ: `SUM(потоки 1…H)/CAPEX*100`;
    - NPV: `G{год 0}+NPV(ставка, G{год 1}:G{год H})`. Функция Excel NPV дисконтирует уже первое
      значение диапазона, поэтому год 0 прибавляется отдельно;
    - TCO, TCO «Как есть» и изменение TCO.
  - Форматы: рубли `#,##0 "₽"`, годы `0.0`, проценты, ставка. Строка заголовков таблиц
    закреплена, ширина столбцов задана. Сценарий с ручным решением везде помечен ⚠.
- **Тесты** (`npx vitest run lib/report/tz`: 3 файла, 30 тестов).
  - Порядок и подписи строк таблицы сценариев, прочерки у «Как есть» и у отказа, примечание к
    ROI услуги, ★ и ⚠.
  - CSV: BOM, «;», CRLF, защита имени «=cmd», порядок разделов, оговорка последней строкой.
  - Книга XLSX читается обратно: 13 листов в нужном порядке. Ячейка NPV содержит формулу, её
    результат совпадает с NPV движка (±1 ₽), и тот же результат получается при независимом
    пересчёте формулы по ячейкам листа. Проверены формулы окупаемости, ROI, TCO и SUM у CAPEX,
    закреплённые заголовки и ⚠ у ручного сценария.
  - Фикстура `test-fixtures.ts` собрана настоящим движком на эталоне T1.2 (цикл 20 пал./ч).
    Сводки имитации в ней условные.
