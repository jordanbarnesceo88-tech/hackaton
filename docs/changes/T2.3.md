### Added — интерфейс имитации склада: схема, управление, показатели, PNG (числа не меняются)

- **`components/sim/**` — клиентский интерфейс имитации sim-1.0.0 (ТЗ §3.6.1, §3.6.3, §3.7.4,
  §4.3.3, §4.5.1).** Выводит то, что считает `lib/sim` (T1.3). Своих чисел не вводит, расчёт
  и имитацию не меняет, поэтому пометки «МЕНЯЕТ ЧИСЛА» нет. Страниц не добавляет: компонент
  подключает рабочая область проекта и `/demo` (T3.1).
  - `warehouse-simulation.tsx` — `WarehouseSimulation({ scenarios, initialKey, readOnly?,
    onSummary?, onAcceptFleet?, nowFn?, headingAs? })`.
    - При открытии и при каждой смене входа прогон идёт без анимации, по частям, с отменой и
      бюджетом 60 с. Затем показываются последний кадр, вердикт и показатели.
    - Движение начинается только по «▶ Старт». Это отдельный прогон с тем же зерном: цикл кадров
      делает speed × 60 × длительность кадра шагов модели. Проигрывание приходит к тем же
      показателям, что и прогон без анимации; в браузере это проверено сравнением строк.
    - Кадр посреди проигрывания: показатели — по пройденной части пикового окна, вердикт и
      узкое место — по полному прогону (на экране и в PNG). Перезапуск сразу показывает
      показатели кадра 00:00, а во время прогрева поясняет, что показатели пикового окна
      появятся после него.
    - Вход, отклонённый предварительной проверкой (робот не поднимает груз, вход вне модели), не
      проигрывается: «▶ Старт» и «↺ Перезапуск» недоступны, часов модели нет ни в показателях,
      ни на схеме, ни в PNG, кнопки «Принять парк по имитации» нет.
    - Строка состояния `aria-live`: «Имитация: выполняется… N %» (шагами по 5 %, а не после
      каждой части прогона), затем «Имитация завершена за N мс · seed S · модель sim-1.0.0».
    - Под схемой — пояснение модели и оговорка «Предварительная оценка, требует обследования
      объекта» (`SIM_FOOTER` из `export-png.ts`: без 'use client', его может импортировать и
      серверный отчёт; текст собран из тех же строк, что подвал PNG).
    - `onSummary` получает итог только по парку «по расчёту»: у двух других вариантов парк
      другой, и в строку «Имитация» таблицы сценариев они не годятся.
    - Если сохранённая сводка сценария получена с тем же парком, зерном и пиковым потоком,
      выводится сверка: «Совпадает с результатом, сохранённым в проекте» или «Отличается…
      Пересчитайте проект» (§3.1.5). Другая версия модели при том же входе — расхождение.
    - Если адаптер передал `provenance`, раскрывается блок «Откуда параметры имитации». Он
      описывает показанный прогон: у вариантов «минимальный по имитации» и «по норме
      организатора» число роботов и зарядных станций — их собственные, с пояснением, откуда
      они; значения строк расчёта (роботы, станции, поток) берутся из входа варианта.
  - `sim-controls.tsx` — только нативные `<button>` и `<select>`.
    - Кнопки «▶ Старт», «❚❚ Стоп», «↺ Перезапуск» (с тем же зерном).
    - Скорость «×1 ×2 ×4 ×8 ×16»: ×1 — минута модели за секунду, по умолчанию ×8. Кнопки
      скорости помечены `aria-pressed`.
    - «Сразу к итогу», «Скачать PNG».
    - Список «Сценарий и парк». В нём «Как есть» недоступен с пометкой «без роботов —
      имитировать нечего», для остальных сценариев — варианты «… — парк по расчёту (N)»,
      «… — минимальный по имитации (M)», «… — парк по норме организатора (K)».
    - «Принять парк по имитации» вызывает `onAcceptFleet(key, M)`. В режиме только для чтения
      кнопки нет. Кнопка недоступна, если парк сценария уже равен M.
  - `sim-kpis.tsx` и `kpi-text.ts` — показатели.
    - Строки: «Рассчитано … пал./ч в пик · Достигнуто …», «Загрузка парка … (в расчёте …)»,
      «Простой», «Зарядка», «Ожидание у точек», «Очередь заданий: макс. …, ожидание p95 … мин»,
      «Узкое место».
    - Значок вердикта: «Расчёт подтверждён имитацией» или «Не подтверждён: {узкое место} —
      минимальный парк по имитации M», а также «парк избыточен» и «вход вне модели».
    - «Время имитации: чч:мм». Рядом с «достигнуто» показан фактически поступивший поток:
      он объясняет разброс по зёрнам.
    - SVG-спарклайн «поступило / выполнено» по пятиминутным интервалам.
    - Таблица «Итоги имитации» из `simSummaryRows`.
    - Если прогон не выполнялся (грузоподъёмность, вход вне модели), вместо «0 %» написано
      «прогон не выполнялся».
  - `variants.ts` — варианты парка и сведения о них.
    - `buildSimVariants`, `simVariantLabel`, `simOptions`, `variantProvenance` — список
      «Сценарий и парк» и «Откуда параметры» по каждому варианту.
    - `storedMatches(stored, calculated)` — сохранённая сводка относится к текущему расчёту:
      то же зерно, тот же парк, тот же пиковый поток (допуск 1e−6) и та же версия модели. Так же
      отбраковывает устаревшие сводки `lib/tz/model.ts` (риски SIM_*).
    - `fleetFacts` / `withFleetFacts` — минимальный парк, парк по норме и вердикт по норме
      берутся из сохранённой сводки только при `storedMatches`. Вердикт по норме — только если
      её парк по норме равен текущему; при показе самого варианта «по норме» — из его прогона.
      После правки параметров или пересчёта до сохранения устаревший минимальный парк не
      попадает ни в значок, ни в «Итоги имитации», ни в `onSummary`, ни в «Принять парк».
  - `draw-scene.ts` — одна функция отрисовки для экрана и для PNG.
    - Цвета холста сохранены: фон `#0f172a`, роботы `#22d3ee`, палитра зон скопирована из
      `ZONE_COLORS` схемы v1.
    - На схеме: зоны с подписями (Приёмка, Хранение, Отгрузка, Зарядка), стеллажи, осевые
      линии проездов (маршруты), ворота с занятостью, зарядные станции.
    - Робот различается формой и цветом: закрашенный квадрат — с грузом, полый круг — без груза,
      жёлтая молния — зарядка (путь, ожидание, заряд). Очередь у ворот и у станции
      вытягивается от точки, поэтому узкое место видно на схеме.
    - Больше 60 роботов не рисуется, в поле схемы пишется «показано 60 из M роботов».
  - `sim-legend.tsx` — легенда с теми же формами и цветами на тёмном фоне. Ворота показаны в
    двух состояниях: полый квадрат — «ворота приёмки и отгрузки свободны», закрашенный — «у
    ворот работает робот» (так же в легенде PNG).
  - `sim-canvas.tsx` — канва и цикл кадров.
    - Цикл requestAnimationFrame читает только ref; показатели уходят в React не чаще
      4 раз в секунду.
    - Скрытая вкладка ставит цикл на паузу, после возврата время не прыгает.
    - При изменении размера (окно или `ResizeObserver`) кадр перерисовывается.
    - Буфер подгоняется под размер канвы × devicePixelRatio (не больше 3).
    - Канва имеет `role="img"` и подпись по вердикту.
  - `export-png.ts` — `exportSimPng(layout, state, summary, meta)`.
    - Собирает лист 2× (2400 px по ширине): схема, легенда в три колонки, вердикт, показатели,
      сценарий, seed, модель, время имитации, дата и оговорка.
    - Скачивание: `toBlob` → `createObjectURL` → `<a download>` → `revokeObjectURL`. Без
      `<img src=blob:>`, который запрещает CSP.
    - Имя файла: `imitaciya-{сценарий латиницей}-seed{n}.png`.
  - Остальные модули:
    - `use-reduced-motion.ts`, `fit-canvas.ts` — шаблоны из схемы v1, скопированы, а не
      импортированы;
    - `playback.ts` — скорости и шаги за кадр;
    - `run-headless.ts` — прогон по частям;
    - `input-key.ts` — ключ входа по значению.
  - При «уменьшении движения» (`prefers-reduced-motion`) по умолчанию показывается итог, а
    «↺ Перезапуск» только ставит прогон в начало (с показателями кадра 00:00) и не запускает
    движение.
- **Как подключать (T3.1).** Варианты строятся так:
  `buildSimVariants({ scenarioName, calculated: model.simInputs[key].calculated, byNorm:
  model.simInputs[key].byNorm, minStableFleet: storedMatches(stored, calculated) ?
  stored.minStableFleet : null, provenance: model.simInputs[key].provenance })`;
  `assumedUtilPct` — `model.simInputs[key].assumedUtilPct`.
- **Тесты (unit, Node): 8 файлов, 89 тестов в `components/sim/*.test.ts`.**
  - Значок робота по фазе и цвет.
  - Отрисовка на записывающем контексте: подписи зон, число полых кругов, часы, отсутствие
    часов у отклонённого прогона, «показано 60 из 70», смещение области для PNG, оба
    состояния ворот в легенде.
  - Ширина проходов по планировке, геометрия и переворот оси Y.
  - Имя файла PNG и транслитерация; `SIM_FOOTER` равен тексту подвала.
  - Подписи вариантов, список с недоступным «Как есть», выбор и откат выбора после пересчёта.
  - «Откуда параметры» по варианту: у «по норме» 3 робота, у «минимального» 9, станции — свои.
  - `storedMatches` и сведения о парках: устаревшая сводка (другой парк, поток, зерно,
    версия модели) не даёт ни минимального парка, ни вердикта по норме.
  - Тексты показателей и вердикта на демо-складе (H1500 × 11: подтверждён; × 3: «парк
    роботов»; груз 2000 кг: «грузоподъёмность»); вердикт полного прогона на кадре посреди
    проигрывания.
  - Сверка с сохранённым результатом (в том числе другой пиковый поток и другая версия
    модели), спарклайн.
  - Прогон по частям: совпадает с `runSimSync` бит-в-бит (кроме `durationMs`), прогресс, отмена,
    бюджет.
  - Шаги за кадр, размер буфера, ключ входа (туда-обратно, включая NaN и ∞).
- **Проверка в браузере (стенд в scratch, не в репозитории).**
  - Реальная модель демо-склада без БД (как `print-demo-numbers --offline`): H1500 N = 11,
    M = 9, K = 3; Carrier P N = 13 (4 станции), M = 12, K = 4 (1 станция).
  - Стенд отдаёт страницу с точной политикой CSP производственной сборки из `next.config.ts`
    (`img-src 'self' data:`, без `blob:`). Нарушений CSP нет (`securitypolicyviolation` пуст).
  - Скачивание PNG проверено перехватом `URL.createObjectURL` и `HTMLAnchorElement.click`,
    без предпросмотра через `<img>` и без настоящего скачивания файла. Ссылка с `download`
    получает адрес `blob:`, Blob — `image/png` около 390 КБ, сигнатура PNG, 2400 px по ширине.
  - Проверку `/demo` под `npm run build && npm start` проводит шлюз W3: только она проверяет
    настоящее скачивание в собранном приложении.
