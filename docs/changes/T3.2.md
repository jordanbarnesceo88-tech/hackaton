### Added — отчёт проекта для печати в PDF, выгрузки XLSX и CSV, стили печати (числа не меняются)

Отчёт и выгрузки строятся из сохранённого расчёта проекта (`ProjectResults`) и ничего не
пересчитывают. Поэтому печатный отчёт, книга Excel и CSV совпадают друг с другом и с рабочей
областью, а повторное открытие проекта даёт те же числа (ТЗ §3.1.5). Выход движка не меняется,
флаг «МЕНЯЕТ ЧИСЛА» не нужен. Требования ТЗ: §2.2 шаг 8, §3.7.1, §3.7.2, §3.7.3, §3.7.5, §3.1.5.

- **Страница `/projects/[projectId]/report`.** Серверная страница: `await connection()`,
  `requireUser()`, проект только владельца (чужой неотличим от несуществующего — 404).
  - Проект без сохранённого расчёта показывает «Сохраните проект, чтобы построить отчёт» и ссылку
    обратно в проект.
  - Шапка: h1 «Отчёт по проекту: {название}», строка «Дата расчёта: дд.мм.гггг чч:мм МСК · модель
    tz-1.0.0 · имитация sim-1.0.0 · данные {хэш}», объект, тип объекта, откуда параметры. Демо-данные
    названы по датасету организатора своего типа объекта: «Склад», «Аэропорт» или «Медучреждение».
  - Выделенная оговорка «Результат является предварительной оценкой и требует верификации при
    обследовании объекта.» — дословно и один раз.
  - Если расчёт сделан другой версией модели, отчёт так и говорит и предлагает пересчитать проект.
  - Если после расчёта изменились данные каталога, нормативы или описания параметров, отчёт тоже
    предупреждает. Проверка та же, что у баннера рабочей области: версия данных на живых данных
    сравнивается с сохранённой. Числа отчёта берутся из снимка, а значения по умолчанию, диапазоны и
    отметки ⚠ в «Параметрах объекта» — из текущих описаний параметров (§3.1.5).
  - Панель (не печатается): «← К проекту», «Печать / Сохранить PDF», «Скачать Excel»,
    «Скачать CSV» — обычные ссылки `<a download>`.
  - Разделы (h2): «Параметры объекта» (все параметры: значение, единица, значение по умолчанию,
    диапазон, источник, ⚠ вне диапазона; каждый раздел параметров один раз, как в форме проекта),
    «Подобранные решения» (решения в сценариях — статус, балл с вкладами факторов, причины,
    ограничения, недостающие данные; все результаты подбора по процессам — статус, балл, причины,
    ограничения и недостающие данные у каждого решения), «Состав оборудования» (роботы, зарядные
    станции, посты диспетчера, ПО управления парком, как получен парк), «Экономика сценариев»
    (`ScenarioTable print`), «CAPEX и OPEX по статьям» (`LineItems print` с формулами и
    происхождением), «Денежный поток», «Чувствительность» (5 сильнейших рычагов на сценарий,
    полный перечень — в Excel), «Имитация» (вердикт, показатели, схема склада в SVG), «Вывод и
    риски», «Формулы» (с источником каждой формулы), «Нормативы и допущения» (значение в расчёте,
    происхождение, обоснование, переопределения в сценариях), «Ограничения модели» (ограничения
    модели и ограничения решений из подбора), «Источники данных» (характеристики продуктов снимка:
    значение, происхождение, подтверждение, дата, ссылка; кириллические адреса показаны без
    %-кодов и punycode, например «морос.рф», а сама ссылка не меняется), «Журнал корректировок».
  - Решение, добавленное вручную, помечено ⚠ во всех разделах, под таблицей сценариев — пояснение.
  - Заголовок вкладки «Отчёт по проекту «…» — Платформа оценки роботизации» — он же имя PDF по
    умолчанию при «Сохранить как PDF».
- **Схема склада в отчёте** (`components/report/tz/layout-svg.tsx`). SVG рисуется на сервере из
  той же планировки `buildWarehouseLayout`, что у имитации и расчёта плеча: зоны приёмки,
  хранения, отгрузки и зарядки, стеллажи, маршруты по осям проездов, ворота и зарядные станции.
  Цвета — как на экране имитации, фон светлый для бумаги. Сценарии с одинаковым числом зарядок
  делят одну схему. Неполные параметры планировки — схемы нет, запасные значения не подставляются.
- **Выгрузки `/projects/[projectId]/export.xlsx` и `/export.csv`** (`components/report/tz/export.ts`).
  - Гость — 401 «Требуется вход», чужой или несуществующий проект — 404 «Проект не найден», проект
    без сохранённого расчёта — 409 «Сначала сохраните проект», ошибка сборки — 500 с подсказкой.
  - XLSX — `buildProjectXlsx` (13 листов с формулами, T2.4), CSV — `projectCsv` (BOM, «;»).
  - Заголовки: `Content-Type`, `Content-Disposition: attachment; filename="project.xlsx";
    filename*=UTF-8''…` (русское имя проекта по RFC 5987, символы, запрещённые в именах файлов,
    заменены «_»), `Cache-Control: private, no-store`. Тело — `new Response(new Uint8Array(…))`.
  - Журнал корректировок в XLSX — те же записи, что в отчёте, с подписями полей из БД.
- **Стили печати** (`app/globals.css`, добавлен блок в конце, прежние правила не менялись).
  `.print-table thead { display: table-header-group }` — заголовок таблицы повторяется на каждой
  странице; `.print-table tr { break-inside: avoid }`; `.report-section { break-before: auto }`.
  Внутри `.report-print` на печати сняты горизонтальная прокрутка и экранные минимальные ширины
  колонок, шрифт таблиц 7,5 pt — чтобы таблица сценариев и денежный поток поместились в ширину
  листа A4. Предпросмотр печати на A4 проверяется на шлюзе W3.
- **Тесты** `components/report/tz/report.test.ts` (38):
  - все разделы в заданном порядке, одно h1;
  - оговорка дословно и один раз, запрещённых для e2e строк нет;
  - все таблицы с `print-table` и не внутри `.report-block`, ⚠ у ручного решения;
  - разделы параметров и группы нормативов не повторяются;
  - не больше пяти строк в каждой таблице чувствительности;
  - у каждого решения подбора вне сценариев есть полные причины, ограничения и недостающие данные;
  - в шапке датасет своего типа объекта, при смене данных есть предупреждение;
  - адреса источников без punycode;
  - плечи из схемы отчёта (`expectedLegsM`) совпадают с плечами, которые посчитала модель проекта
    `buildProjectModel`;
  - коды 401/404/409/500 и заголовки выгрузок, BOM у CSV и zip-сигнатура у XLSX.
