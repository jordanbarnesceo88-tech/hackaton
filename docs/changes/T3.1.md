### Added — рабочая область проекта, «Мои проекты», «Новый проект», гостевой /demo (числа не меняются)

Путь жюри по ТЗ §5.4 — «создать проект → подобрать решения → сравнить сценарии → показать расчёт
→ запустить визуализацию» — теперь проходится в интерфейсе: от списка проектов до сохранения и
выгрузок. Все числа считает прежний движок `buildProjectModel` (lib/tz/model) без изменений,
поэтому флаг «МЕНЯЕТ ЧИСЛА» не нужен. Числа гостевого /demo для склада совпадают с засеянным
демо-проектом `demo-warehouse` по каждому сценарию (NPV, CAPEX, TCO) и по версии данных
(`7be2cba2`) — ТЗ §5.6. Требования ТЗ: §2.1.1, §2.2 шаги 1–8, §3.1.1–§3.1.3, §3.1.5, §4.3.1,
§4.5.4, §5.4, §5.5.

- **Рабочая область `components/project/workspace.tsx`** (`'use client'`). Весь путь §2.2 на одной
  странице: восемь секций с якорями `#object`, `#params`, `#selection`, `#comparison`,
  `#economics`, `#scenarios`, `#simulation`, `#report`. Заголовки h2 — «Шаг N из 8 · …».
  - Липкая строка над шагами: навигация по шагам, кнопка «Пересчитать» и строка состояния
    (`aria-live`) «Расчёт выполнен за … мс · модель tz-1.0.0 · данные …». В строке также статус
    имитации и баннер «Параметры изменены — нажмите «Пересчитать»».
  - Правка параметра модель не пересчитывает: так устроен шаг 5 легенды датасета организатора.
    Законченные действия со сценариями пересчитывают модель сразу. Это выбор решения, ручное
    добавление, корректировка, новый сценарий и «Принять парк по имитации».
  - Пересчёт идёт в обработчике события через `timed(() => buildProjectModel(…), performance.now)`.
    На сервере работает та же функция, поэтому числа в браузере и в сохранённом проекте совпадают.
  - Шаг 2: параметры можно загрузить из Excel/CSV по шаблону. В журнал попадают только значения,
    которые отличаются от текущих, с причиной «значение из файла «…»».
  - Шаг 3: подбор показан по каждому процессу объекта. У процессов без экономики есть бейдж
    «Экономика для процесса в прототипе не рассчитывается».
    - «Использовать в сценариях» создаёт сценарий покупки. Если у продукта есть ставка, создаётся
      и сценарий услуги (RaaS).
    - «Добавить вручную» создаёт сценарий «Покупка — … (вручную)» с пометкой ⚠ и записью в журнал.
  - Шаг 5: по вкладке сценария показаны состав, CAPEX и OPEX по статьям, денежный поток,
    «Как посчитано», а также нормативы с корректировками сценария.
  - Шаг 6: таблица сценариев со строкой «Имитация». По вкладкам — чувствительность, ниже вывод.
    Кнопки «Добавить сценарий» (покупка или услуга, решение из подбора), «Копировать сценарий» и
    «Удалить сценарий» работают в пределах 3–10 сценариев.
  - Шаг 7: имитация склада. Для аэропорта и медучреждения вместо неё статичная схема.
  - Шаг 8: панель действий и журнал корректировок.
  - Имитация для таблицы сценариев: после каждого пересчёта в браузере по очереди прогоняются
    парк по расчёту, парк по норме организатора и подбор минимального устойчивого парка.
    - Это те же прогоны, что делает сервер при сохранении. Они идут с отменой, уступкой
      управления странице и общим бюджетом 60 с (§4.3.3).
    - Затем модель собирается ещё раз со сводками, чтобы в сценарии попали риски
      SIM_NOT_CONFIRMED и SIM_OVERSIZED.
    - Сохранённый проект до первого пересчёта показывает сохранённые сводки.
  - Журнал: корректировки ключей `param:<key>`, `item:<процесс>:<поле>`, `norm:<ключ>`,
    `scenario:add` и `scenario:remove` видны сразу. На сервер они уходят при «Сохранить проект».
    - Причина «принят парк по имитации» ставится автоматически при «Принять парк по имитации».
    - Оценка ставки RaaS записывается как `item:<p>:raasRate` с пометкой «оценка». Ручная ставка
      или «вернуть расчётное» пометку снимают.
- **Панель действий `project-toolbar.tsx`**. У владельца: «Сохранить проект» (серверное действие;
  сообщения «Проект сохранён ЧЧ:ММ» или «Не удалось сохранить: …. Попробуйте ещё раз»),
  «Отчёт (PDF)», «Excel», «CSV», «Копировать проект», «Удалить проект».
  - Удаление просит подтверждение: «Удалить проект «…» со всеми сценариями и журналом? Действие
    необратимо.».
  - Excel и CSV строятся сервером по сохранённому расчёту, поэтому при несохранённых правках
    недоступны («сначала сохраните проект»).
  - У гостя: «CSV» собирается в браузере (BOM, `;`, CRLF) и есть ссылка «Войти, чтобы сохранить
    проект».
  - У засеянного демо-проекта кнопки сохранения, удаления и пересчёта на сервере закрыты с
    подсказкой «скопируйте его». Копирование открыто.
- **Баннер версий `version-banner.tsx`** (§3.1.5). Показывается, если модель или живые данные
  каталога, нормативы или описания параметров изменились после расчёта. Текст: «Показан расчёт
  от … (модель …, данные …). С тех пор изменились …». Кнопка «Пересчитать на актуальных данных»
  вызывает серверный пересчёт, после чего страница открывается заново на новом снимке.
- **Статичная схема `facility-schematic.tsx`** (§5.5, §5.7). SVG строится по
  `generateLayout(mapKind(facility), площадь)` из lib/scene (только импорт). На схеме зоны с
  подписями, типовой маршрут и точки операций, над ней бейдж «Прототип: экономика и имитация
  реализованы для склада». Подпись честно говорит, что схема условная.
- **`/demo`** — гостевой расчёт без сохранения (§3.1.2). Параметры — базовые значения датасета
  организатора, сценарии — те же сценарии по умолчанию, что у «Нового проекта» (`initialProject`).
  - Тип объекта задаётся в адресе: `/demo`, `/demo?facility=airport`, `/demo?facility=medical`.
    Страница переключается ссылками.
  - h1: «Демо-расчёт на данных организатора: Склад | Аэропорт | Медучреждение».
- **`/projects`** — «Мои проекты». Колонки: проект, тип объекта, число сценариев, дата изменения
  (МСК), лучшая окупаемость. Действия «Открыть», «Копировать», «Удалить»; кнопка «Новый проект»;
  ссылки на /demo и на «Расчёты в упрощённой модели v1» (/analyses).
- **`/projects/new`** — «Новый проект» (Шаг 1 из 8 · Объект).
  - Поля: название («Например, РЦ Подольск»), объект, тип объекта плитками (radiogroup).
  - Источник параметров: «Демо-данные организатора», «Загрузить Excel/CSV по шаблону» (файл
    проверяется ещё раз на сервере) или «Заполнить вручную (от базовых значений)».
  - Кнопка «Создать проект»; ошибки выводятся через `role=alert`.
- **`/projects/[projectId]`** и `loading.tsx` («Загружаем проект…»). Первый показ воспроизводит
  расчёт из снимка проекта: сохранённые параметры и сценарии, снимки продуктов и нормативы,
  сводки имитации. Для `demo-warehouse` воспроизведение совпадает с сохранёнными результатами
  бит-в-бит. Чужой проект неотличим от несуществующего (404).
- Каждая страница с БД начинается с `await connection()`. Пропсы `params` и `searchParams` имеют
  тип `Promise`. На каждой странице ровно одно h1, запрещённые строки плана §6 не используются.

Проверено вручную на `next dev` при 1366×768. Сценарий /demo: 8 шагов; таблица сценариев
на 5 колонок; строка «Имитация» с тремя «✓ подтверждено»; расчёт за 54–161 мс. Отработали
правка параметра с пересчётом, «Использовать в сценариях», «Добавить вручную», копирование,
удаление и добавление сценария, «Принять парк по имитации» и гостевой CSV. Со всеми 119 раскрытыми
блоками `<details>` страница не выходит за ширину экрана. Страницы владельца проверены серверным
рендером и путём данных страницы: вход демо-аккаунтом из агента не выполнялся, путь с входом
закрывают e2e T4.1.
