### Added — загрузка параметров объекта из Excel/CSV и шаблоны (числа не меняются)

ТЗ §2.2 шаг 2, §3.2.3–§3.2.5, §4.4.6. Задача собирает в одно целое то, что сделано в T1.5
(разбор и проверка файла, шаблон) и T1.8 (описания параметров из БД). Расчётная модель не
менялась, поэтому числа прежние.

- **`GET /api/templates/{facility}?format=xlsx|csv`** — шаблон параметров для склада
  (`warehouse`), аэропорта (`airport`) и медучреждения (`medical`).
  - Описания берутся из администрируемой таблицы `ParamDefinition`. Поэтому шаблон всегда
    совпадает с тем, что потом проверяет загрузка.
  - `format=xlsx` отдаёт книгу с листами «Параметры» и «Как заполнить». Без параметра или с
    любым другим значением отдаётся CSV для русского Excel: BOM, «;», десятичная запятая,
    CRLF. Первая строка CSV — `Ключ;Раздел;Параметр;Единица;Значение;Мин;Макс;Обязательный;Пример;Источник/примечание`.
  - Столбец «Значение» заранее заполнен демо-значениями организатора. Рядом стоят единица,
    диапазон, пример и источник каждого значения по умолчанию (§3.2.5).
  - Файл называется «Шаблон параметров — Склад.xlsx» и т. п. Кириллица передаётся в
    `filename*=UTF-8''…`, а ASCII-имя `params-warehouse.xlsx` — запасное для старых клиентов.
    Заголовок `Cache-Control: private, no-store`.
  - Неизвестный тип объекта даёт 404 с текстом по-русски. Имена вроде `constructor` тоже не
    проходят. Если параметры ещё не засеяны, ответ 503 «выполните npm run db:seed». Если база
    недоступна, тоже 503, а причина пишется только в лог сервера.
  - Вход не нужен: в шаблоне нет данных пользователей, а загрузить файл может и гость
    (§3.1.2).
- **Действие `parseParamsFileAction(facility, prev, formData)`**
  (`lib/projects/import-action.ts`) проверяет файл и возвращает `ImportState`:
  - `status: 'ok'` — файл прочитан. Действие возвращает полный набор значений (`values`),
    строку отчёта на каждый параметр (`report`: параметр, значение с единицей, статус, что
    сделать, номер строки файла), вид таблицы (шаблон платформы или лист организатора с
    именем листа) и итог `{found, errors, warnings}`.
  - `status: 'error'` — файл целиком не принят, `message` говорит, что сделать.

  Проверки по порядку:
  1. тип объекта из списка;
  2. лимит 30 проверок за 15 минут с одного IP (`upload:ip:…`);
  3. файл выбран и не пустой;
  4. размер не больше 950 000 байт («Файл больше 950 КБ — удалите лишние листы и повторите»);
  5. разбор `parseParamsFile` по описаниям из БД.

  **Файл нигде не сохраняется** (§4.4.6): он разбирается в памяти и отбрасывается. Поэтому
  действие доступно без входа, а при удалении проекта удалять нечего.
- **Компонент `ImportForm({ facility, onApply, compact? })`**
  (`components/project/import-form.tsx`):
  - ссылки «Скачать шаблон Excel» и «Скачать шаблон CSV» (обычные `<a download>`);
  - поле выбора файла `.xlsx,.csv` и кнопка «Проверить файл»;
  - подсказка «Можно загрузить и исходный лист организатора (Датасеты_хакатон.xlsx) — строки
    сопоставляются по названию параметра»;
  - итог «Найдено N параметров, ошибок E, предупреждений W» с названием распознанного листа;
  - таблица отчёта «Параметр | Значение | Статус | Что сделать». Статусы: «ок», «по
    умолчанию», «предупреждение», «ошибка». Ошибки выделены цветом ошибки. Если в файле есть
    проблемы, по умолчанию показаны только они, а флажок показывает все строки;
  - кнопка «Применить значения» передаёт проверенный набор в `onApply(values, { fileName })`.
    При ошибках в файле, для непроверенного нового файла и после смены типа объекта кнопка
    недоступна.

  Проверено на настоящем `Датасеты_хакатон.xlsx` организатора (файл читался из «Загрузок» и в
  репозиторий не добавлялся):
  - «Склад» — найдено 42 параметра, 0 ошибок, 0 предупреждений; ещё 10 дополнений
    (PARAM_EXTRAS) взяты по умолчанию;
  - «Аэропорт» — 39 параметров, 0 ошибок;
  - «Медучреждение» — 57 параметров, 0 ошибок.

  Наш CSV- и XLSX-шаблон читаются обратно без ошибок.

#### Для встраивания (T3.1)

- `ImportForm` не рисует собственный `<form>`, потому что его вкладывают в форму создания
  проекта, а вложенные формы в HTML недопустимы. Файл отправляется программно, у поля выбора
  нет `name`, поэтому вместе с внешней формой файл не уходит. Обе кнопки имеют
  `type="button"`.
- Размер файла проверяется ещё до отправки. Тело больше 1 МБ Next отклоняет раньше, чем
  действие успевает ответить, и без этой проверки ошибка ушла бы в границу ошибок страницы.
  Сбой сети или «Failed to find Server Action» после обновления сборки превращается в
  сообщение «Обновите страницу и проверьте файл ещё раз».
- `values` — это `ParamValues`, полный набор по всем параметрам объекта: где значения в файле
  нет, стоит значение по умолчанию. В таблице такие строки помечены «по умолчанию». Изменения
  относительно текущих значений проекта сравнивает и пишет в журнал вызывающий код.
