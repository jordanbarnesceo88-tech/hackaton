### Added — параметры объекта: значения по умолчанию, проверка, загрузка CSV/XLSX, шаблон (числа не меняются)

- **`lib/files/csv.ts` — CSV без зависимостей, работает на сервере и в браузере**
  (ТЗ §3.2.3, §3.7.3):
  - `parseCsv(text)`:
    - срезает BOM и сама определяет разделитель: «;» или «,», табуляцию — если других нет;
    - понимает поля в кавычках, удвоенные кавычки, переводы строк внутри поля, CRLF, LF и CR.
  - `toCsv(rows, { decimalComma: true })` пишет для русского Excel:
    - BOM, разделитель «;», CRLF, числа с десятичной запятой и без разделителей разрядов;
    - кавычки там, где они нужны;
    - **защиту от формул**: текст, начинающийся с `=`, `+`, `-`, `@`, получает апостроф
      (`'=SUM(A1)`). Отрицательные числа не трогаются.
  - `parseRuNumber("2 700 000,00") → 2700000` понимает:
    - неразрывный, узкий и тонкий пробелы;
    - типографский минус;
    - группы разрядов через точку.

    Если запись неоднозначна (`2,700,000`), возвращает `null`.
  - `decodeText(bytes)` раскодирует:
    - UTF-8;
    - UTF-16 с BOM («Текст Юникод» из Excel);
    - Windows-1251 — так сохраняет CSV русский Excel.
- **`lib/tz/params` — схема и проверка параметров (ТЗ §3.2.2–§3.2.5, §4.5.3).**
  - `applyDefaults(defs, values)` дополняет значения до полного набора базовыми значениями
    организатора.
  - `coerce(def, raw)` приводит ввод к типу параметра: число, целое, процент, перечисление,
    текст, габариты «Д×Ш×В».
  - `isOutOfRange(def, v)` проверяет диапазон с допуском на двоичную арифметику.
  - `validateParamValues(defs, raw, { origin: 'manual' | 'upload' | 'api' })` возвращает
    `{ values, issues }`. Коды проблем и их уровни:

    | Код | Уровень | Когда |
    |---|---|---|
    | `missing_required` | ошибка | обязательное поле пустое |
    | `wrong_type` | ошибка | значение не того типа |
    | `bad_number_format` | ошибка | число записано с ошибкой |
    | `negative` | ошибка | отрицательное значение |
    | `not_integer` | ошибка | дробное там, где нужно целое |
    | `bad_option` | ошибка | значения нет среди вариантов |
    | `unknown_key` | ошибка | лишний параметр в файле или API; в ручном вводе пропускается |
    | `duplicate_key` | ошибка | параметр указан дважды |
    | `unit_mismatch` | ошибка | единица не совпадает с единицей параметра |
    | `out_of_range` | предупреждение | вне диапазона организатора; значение принимается и подсвечивается |
    | `locked_changed` | предупреждение | изменено зафиксированное значение (min = max); правка идёт в журнал |

    Сообщение по-русски объясняет, что не так и как это исправить. Например: «Средняя з/п
    оператора погрузчика (gross): единица «тыс. руб./мес.» не совпадает с «руб./мес.» —
    пересчитайте значение в руб./мес.».

    При ошибке в `values` остаётся значение по умолчанию, так что набор всегда полный.
    Решение «сохранять или нет» принимает вызывающий код через `hasErrors(issues)`.
  - Единицы сравниваются с учётом синонимов: «руб./мес.» = «₽/мес», «м/п» = «паллетомест»,
    «мм/2м» = «мм/2 м», «поддон» = «паллет».
  - Единицу, дописанную к числу, можно писать синонимом: «20 000 м2», «20 000 кв. м», «5 шт».
    Если дописана другая единица («2 га» в поле в м²), проверка сообщает `unit_mismatch` с
    подсказкой «пересчитайте значение в м²», а не «не число».
  - **CSV русского Excel в Windows-1251.** В этой кодировке нет «²», «×», «−» и «₽», и Excel
    пишет вместо них «?». Поэтому «?» и U+FFFD считаются одним потерянным знаком:
    - в единицах «м?» совместима с «м²», а «?/мес» — с «₽/мес»;
    - в габаритах «1200?800?1600» читается как «1200×800×1600»;
    - в перечислениях «Морозильный (ниже ?18 °C)» принимается, если под такой ввод подходит
      ровно один вариант.

    Без этого лист организатора, сохранённый как обычный CSV, давал ошибки: 4 на листе
    «Склад», 3 на «Аэропорте», 1 на «Медучреждении». Загрузку с такими ошибками применить
    нельзя. Теперь ошибок 0 на всех трёх листах. Проверено на описаниях T1.1.
- **Загрузка параметров из файла (ТЗ §2.2 шаг 2, §3.2.3).**
  `parseParamsFile(bytes, fileName, defs)` в `lib/tz/params/import.ts` работает только на
  сервере и принимает `.xlsx` и `.csv`. Остальные форматы получают ответ «Поддерживаются
  файлы .xlsx и .csv по шаблону»; для `.xls` добавлено, как его пересохранить.
  - Распознаются два вида таблиц:
    - **наш шаблон** — строка заголовков со столбцами «Ключ» и «Значение»;
    - **лист датасета организатора** — выбирается по типу объекта: «Склад», «Аэропорт»,
      «Медучреждение». Заголовок ищется по «Параметр» и «Базовое значение». Строки
      сопоставляются по названию в три прохода: точное название, суть без скобок и
      «Из них:», общие основы слов.
  - Единица не отсекает кандидата при сопоставлении, а только разбивает ничью. Строка,
    найденная по названию, но с чужой единицей, сопоставляется, и отчёт показывает ошибку
    `unit_mismatch`. Раньше такая строка молча оставалась незагруженной.
  - Строку организатора, которую не удалось сопоставить, отчёт помечает предупреждением, а
    не ошибкой: загрузку остальных она не блокирует.
  - Числа в процентном формате Excel читаются так, как их видит пользователь. Если ввести
    «7%» в ячейку «Значение», Excel хранит 0,07 в формате «0%». Такая ячейка читается как
    «7%» и даёт 7, потому что проценты у параметров хранятся целыми. Раньше она молча давала
    0,07. В поле, которое не в процентах, такое значение даёт ошибку единицы.
  - Результат: полный набор значений и отчёт по каждому параметру. Статусы отчёта: «ok»,
    «defaulted» (с источником значения по умолчанию) или проблема проверки.
  - Файл разбирается в памяти и не сохраняется (§4.4.6).
  - Проверено на настоящем `Датасеты_хакатон.xlsx` (только чтение, в репозиторий файл не
    попал); итог — в разделе «Тесты» ниже.
- **Шаблон параметров** со столбцами «Ключ | Раздел | Параметр | Единица | Значение | Мин |
  Макс | Обязательный | Пример | Источник/примечание»:
  - `paramsTemplateCsv(defs)` собирает CSV через `toCsv`.
  - `writeParamsTemplateXlsx(defs)` собирает XLSX (только сервер, exceljs):
    - лист «Параметры» с закреплённой строкой заголовков, ширинами столбцов и фильтром;
    - «Значение» заполнено значениями по умолчанию и выделено цветом;
    - у перечислений — выпадающий список, у чисел — мягкая проверка диапазона в Excel;
    - второй лист «Как заполнить».
  - В столбце «Источник/примечание» для каждого параметра указано:
    - происхождение значения по умолчанию и ссылка на место у организатора;
    - формула и основание для расчётных и оценочных значений;
    - примечание организатора;
    - отметка «зафиксировано организатором».

    Так выполняется требование ТЗ §3.2.5 показывать значения по умолчанию и источник
    каждого норматива.
- **`lib/tz/params/coverage.ts`** — сверка процессов с параметрами. `processParamKeys` и
  `missingProcessParamKeys` называют ключи, на которые ссылаются `PROCESS_DEFS`, но которых
  нет среди описаний объекта.

  - Перекрёстная проверка с настоящими описаниями T1.1 (`lib/data/organizer/params.ts`)
    запускается в каждом прогоне и проходит. Она проверяет, что:
    - каждый ключ процессов описан;

    - шаблон каждого объекта читается обратно в значения по умолчанию;
    - шаблон и лист в раскладке организатора, сохранённые в Windows-1251, читаются без
      ошибок для всех трёх объектов.
  - Настоящий `Датасеты_хакатон.xlsx` проверен против настоящих описаний T1.1 (только
    чтение). Сопоставлено: Склад 42, Аэропорт 39, Медучреждение 57. Ошибок и предупреждений
    нет, значения равны значениям по умолчанию.

Числа расчёта не меняются: модуль только проверяет и загружает параметры. Экономика и
нормативы не затронуты.
