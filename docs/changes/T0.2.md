### Added
- **Модель данных по методике ТЗ (tz-1.0.0): миграция `20260924120000_tz_v2`.** Миграция
  только добавляет. В ней четыре перечисления: `Role`, `CharGroup`, `CatalogOrigin`,
  `ScenarioKind`. Есть колонка `User.role` с `DEFAULT 'USER'`, так что существующие
  пользователи получают обычную роль без бэкфилла. Добавлено двенадцать таблиц:
  - `Process`, `FacilityTypeProcess`, `SolutionType`: звено «процесс» в иерархии ТЗ §3.3.1;
  - `CatalogProduct`, `ProductProcess`;
  - `ProductCharacteristic`: провенанс по каждой характеристике (источник, дата,
    подтверждение, альтернативные значения), закрывает ТЗ §3.3.4;
  - `ParamDefinition` и `Norm`: справочники параметров и нормативы, которые правит
    администратор (ТЗ §3.1.4, §3.2.6);
  - `DataRelease`;
  - `Project` и `Scenario`: проекты с тремя и более сценариями, версии модели и данных,
    снимок расчёта (ТЗ §3.1.3, §3.1.5);
  - `ChangeLog`: журнал ручных корректировок и действий администратора (ТЗ §3.5.4).

  Удаление проекта каскадом удаляет его сценарии и журнал (ТЗ §4.4.6). SQL сгенерирован
  командой `prisma migrate diff --script`, а не `migrate dev`, и вычитан вручную. В нём нет
  ни одного DROP, RENAME или ALTER COLUMN. Таблицы v1 (`Solution`, `Assumption`,
  `SavedAnalysis` и остальные) не менялись.
- **Зависимость `exceljs` 4.4.0** для серверной выгрузки XLSX. Она добавлена в
  `serverExternalPackages` в `next.config.ts`, CSP не изменён. `npm audit` отмечает у неё
  одну уязвимость средней важности через `uuid@8`.
- **Скрипты npm**: `gen:organizer` (`scripts/gen-organizer-seed.ts`, задача T1.1),
  `demo:numbers` (`scripts/print-demo-numbers.ts`, T2.2), `check:fresh`
  (`scripts/fresh-instance-check.ts`, T1.7). Сами скрипты появятся в этих задачах.
- **Правило ESLint для `lib/sim/**`.** В имитации запрещены `Date`, `performance`,
  `Math.random`, `Math.sqrt` и `Math.log`. Имитация должна давать бит-в-бит одинаковый
  результат в Node (при сохранении проекта) и в браузере.
- **Набор тестов `db` в `vitest.config.mts`** заранее включает БД-тесты новой модели:
  `lib/catalog/queries.test.ts`, `lib/catalog/sync.test.ts`, `lib/projects/actions.test.ts`,
  `lib/admin/actions.test.ts`. Устаревшие числа в комментарии («319», «двадцать семь»)
  заменены описанием разделения наборов без чисел.

### Fixed
- **Дрейф схемы `FacilityTypeCategory`.** Миграция `20260907120000_global_categories`
  писалась вручную и создала оба внешних ключа этой таблицы без `ON UPDATE CASCADE`, то есть
  с `NO ACTION`. Умолчание Prisma — `Cascade`, поэтому
  `prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --exit-code`
  возвращал 2 даже на полностью применённой истории. Любая следующая сгенерированная
  миграция потащила бы `DROP CONSTRAINT`/`ADD CONSTRAINT`. В `schema.prisma` у двух
  связей теперь стоит `onUpdate: NoAction`, то есть схема описывает то, что уже стоит в базе.
  SQL не выполнялся, поведение не изменилось: id — cuid и не обновляются. После правки diff
  возвращает 0 и до миграции, и после неё.

Числа модели не меняются: задача не трогает ни расчёт v1, ни расчёт новой модели.
