## Подтверждённые дефекты и исправления

1. **Блокировка сервера тяжёлым расчётом.** До исправления один запрос N60/C5 задерживал `/api/health` на 3,45 с, три параллельных — на 10,23 с. Живые HTTP-пути переведены на кооперативные прогоны с передачей управления I/O, проверкой дедлайна внутри цикла и общим допуском двух задач на процесс. Третий запрос получает 503 с `Retry-After: 2`, без записи. Бюджет вычисления проекта — 60 с; пространственной проверки всего проекта — 15 с. Это не гарантированный срок сетевого ответа или фиксации БД. Синхронные функции сохранены для офлайн-инструментов и проверки эквивалентности.
2. **Допустимый большой проект не сохранялся из-за транспортных лимитов.** Реально валидный по структуре пример из десяти сценариев занимает 2 433 182 байта JSON. Прежние ограничения составляли 200 000 байт API и 1 МиБ Server Action. Теперь общий предел входного JSON — 4 МиБ UTF-8, с проверкой на клиенте и сервере; лимит оболочки Server Action — 5 МиБ. Прежние ограничения полей и смысловые валидаторы продолжают действовать. При превышении лимита пользователь получает понятную причину, правки остаются во вкладке. Это конечный общий предел, а не обещание поддержать одновременные максимумы каждого поля.
3. **Сборка могла успешно выпускать битый standalone HTML.** Отсутствующий/повторный маркер шаблона и синтаксически ошибочный `app.js` раньше завершались кодом 0. Теперь проверяется единственность маркеров, JSON-конфигурация и синтаксис всего выпущенного классического JavaScript, включая общую область имён. Обе страницы проверяются до записи. `build:3d` включён в обычную сборку; `check:3d` и CI обнаруживают устаревший HTML. Esbuild объявлен прямой фиксированной зависимостью.
4. **Неизмеренные нули выглядели результатом проверки.** Для `NOT_EVALUATED` риск больше не сообщает «достигнуто 0, очередь 0»: он прямо говорит, что поток, очередь и ожидание не оценены. Такой сценарий по-прежнему не получает подтверждённую рекомендацию; денежные формулы и старые архивы не изменяются.
5. **Отмена во время записи могла быть проигнорирована.** Независимый ревьюер воспроизвёл отмену после CAS-claim внутри транзакции. Добавлена проверка перед завершением транзакции; тест с настоящим Postgres подтверждает откат ревизии, результата, сценариев и журнала. Уже зафиксированная атомарная операция создания не может быть отменена задним числом: потеря ответа после commit требует проверки списка проектов, а не обещания абсолютной отмены.
6. **Побайтная воспроизводимость зависела от Windows/Linux.** Эквивалентные исходники с LF и CRLF выпускали разные HTML. Генератор теперь нормализует окончания строк до LF, а `.gitattributes` сохраняет это правило при checkout. Сравнение реальных сборок из LF/CRLF/смешанного набора даёт одинаковый SHA. Исторический CSV отдельно защищён от преобразования строк, чтобы сохранить принятый SHA.

## Что нельзя заключать из проверки

`simInputIdentity` — каноническая сериализация входа, **не криптографическая подпись**. Защиту сохранённого результата обеспечивает самостоятельный серверный прогон канонического входа, а не доверие цифрам клиента.

Предыдущий прогон 50 пользователей проверял чтение и навигацию, не 50 одновременных тяжёлых расчётов. Два вычислительных слота на процесс обеспечивают конечный допуск; это не распределённая очередь и не промышленный SLA. Проверенные большие JSON также не доказывают масштабируемость БД на тысячи проектов.

Реальное сохранение большого проекта подтверждено отдельно: 2 433 182 байта JSON, десять сохранённых сценариев, ревизия 1→2, 43,16 с полного функционального запроса. Пространственный успех этим фактом не объявляется. Фактический `results` этого проекта занял 5,18 МБ, ответ Server Action — около 9,96 МБ: повторение данных остаётся измеренным ограничением. Вход 4 503 182 байта получил отказ действия без изменения БД; клиентская проверка сохранила черновик и не отправила запрос. Для проверки клиентского предела использована явно обозначенная тестовая инъекция состояния формы, а не выдуманный публичный импорт JSON.

Девять замечаний комиссии отработаны в обозначенном объёме прототипа; CAD-импорт и промышленный контур развёртывания/интеграций оставлены будущими задачами.
