# Задача: собрать вендорские строки для каталога промышленных роботов, с проверяемыми источниками

Ты собираешь данные для калькулятора окупаемости роботизации. Каталог показывают людям,
которые будут спорить с цифрами, поэтому единственная ценность строки — в том, что каждую
её цифру можно открыть по ссылке. Строка без источника хуже отсутствующей строки: отсутствие
честно, а выдуманная спека разрушает доверие ко всему остальному.

## Железное правило

Строка заводится, только если найдены **оба конца**:

1. **Производительность** — страница производителя с пропускной способностью ОДНОЙ единицы;
2. **Цена** — страница, где цена реально опубликована числом.

Если хотя бы один конец не найден — **строка не заводится**. Не оценивай, не интерполируй,
не пересчитывай из «похожей модели того же вендора», не бери цифру из обзора или пресс-релиза
третьих лиц. Ненайденная цена — это результат, который идёт в отчёт отдельной строкой, а не
пробел, который надо чем-то закрыть.

«Нашёл 4 модели из 12 намеченных» — нормальный отчёт. «Нашёл 12», где три цены прикинуты, —
брак, который придётся выбрасывать целиком, потому что доверия не останется ни к одной из
двенадцати.

## Что считается производительностью (здесь ломается чаще всего)

Нужен **поток одной единицы за единицу времени**.

**Не подходит и не заменяет:** грузоподъёмность (кг), скорость перемещения (м/с), время
работы от батареи, объём бака или бункера, высота подъёма, точность позиционирования,
производительность всей системы или парка («склад обрабатывает до 1000 заказов/час»),
маркетинговое «до 3 раз быстрее человека».

**Подходит:** м²/час уборки; отборов/час; коробок/час; паллет/час; посылок/час;
доставок/сутки; помещений/сутки; тотов/час; деталей/час инспекции.

Если производитель даёт диапазон («2000–3500 м²/ч»), бери **нижнюю границу** и запиши
диапазон в примечание. Если производитель даёт цифру «в идеальных условиях» и отдельно
«практическую» — бери практическую.

## Что считается ценой

Опубликованное число на странице, которую можно открыть. Годятся: интернет-магазин
дистрибьютора, страница «купить» с ценником, листинг на Alibaba / Made-in-China с
указанной ценой, официальный прайс-лист в PDF.

Не годится: «цена по запросу», «от $X» без верхней привязки в статье-обзоре, цена из
новости или поста в LinkedIn, цена из чужого калькулятора.

Приоритет — **цена покупки**. Если опубликована только аренда (RaaS, $/мес), запиши её в
отдельное поле отчёта как аренду и **не превращай в цену покупки** умножением на срок.
Если страница даёт цену не в долларах — запиши исходную валюту и число как есть; пересчёт
сделаем сами по датированному курсу.

## Формат результата

Для каждой найденной модели верни объект такого вида (это сокращённая форма строки сева —
эксплуатационные расходы мы считаем сами, их искать не нужно):

```ts
{
  categorySlug: "class-cleaning",              // из таблицы категорий ниже
  name: "Gausium Scrubber 75",                 // как называет модель производитель
  vendor: "Gausium",
  priceUsd: 95880,                             // число с priceSourceUrl; null, если цена не в USD
  priceOriginal: null,                         // напр. "CNY 690000" или "RaaS $2669/мес", если не USD-покупка
  priceSourceUrl: "https://www.robotlab.com/cleaning-robots/store/scrubber-75-cleaning-robot",
  capacityPerUnit: 3000,                       // поток ОДНОЙ единицы
  capacityUnit: "м²/час",                      // по-русски, см. правило единиц ниже
  capacityBasis: "PER_HOUR_FLOW",              // PER_HOUR_FLOW | PER_DAY_FLOW | CONCURRENT_STOCK
  sourceUrl: "https://gausium.com/specs/scrubber-75/",   // страница производителя со спекой
  lastVerified: "2026-09-09",                  // дата, когда ты реально открыл обе страницы
  specs: { scrubbingWidthMm: 750, cleanWaterTankL: 75 }, // только опубликованные числа
  notes: "цена — покупка; RaaS $2669/мес на той же странице"
}
```

`capacityBasis`:
- `PER_HOUR_FLOW` — производительность дана за час;
- `PER_DAY_FLOW` — за смену или за сутки;
- `CONCURRENT_STOCK` — единица обслуживает одновременно N объектов (мест хранения, коек,
  постов), а не поток за время. Встречается редко; если сомневаешься — не эта.

## Единица измерения обязана совпадать с типом нагрузки категории

В движке две несовместимые шкалы, и путаница между ними даёт правдоподобное, но неверное
число (робот-уборщик «заменял» кладовщиков, потому что м² сравнивались с отборами).

- `class-cleaning` — поток **площади**: единица обязана быть в м² (`м²/час`, `м²/смена`).
- **Все остальные категории** — поток **операций**: единица обязана быть **какой угодно,
  кроме м²**.

Тест в репозитории падает на нарушении, так что строка с неверной единицей до каталога
не дойдёт.

## Что вернуть

Один markdown-файл со **тремя** разделами:

1. **Заведённые строки** — массив объектов в формате выше. Только те, где найдены оба
   конца.
2. **Не заведено** — таблица: модель, вендор, категория, что нашлось, чего не нашлось,
   где искал. Этот раздел так же важен, как первый: он показывает, что поиск был, и не даёт
   искать это же второй раз.
3. **Замечания** — противоречия между источниками (производитель и дистрибьютор дают разную
   спеку), подозрительные цифры, случаи, где производительность опубликована только по
   парку, вендоры без публичной документации вообще.

Файл сохрани как `docs/research/vendor-candidates-<дата>.md`, если работаешь в репозитории;
иначе просто выведи в ответ.

## Чего не делать

- Не подставлять цену «по аналогии с похожей моделью» — ни одной.
- Не брать спеку из обзора, блога или пресс-релиза, если есть страница производителя;
  если страницы производителя нет — строка не заводится.
- Не переводить производительность парка в производительность единицы делением на число
  роботов: состав парка и условия обычно не опубликованы.
- Не считать грузоподъёмность, скорость или время работы производительностью.
- Не сглаживать отчёт. Пустой раздел «не заведено» при десятке заведённых строк — признак,
  что правило нарушено.
