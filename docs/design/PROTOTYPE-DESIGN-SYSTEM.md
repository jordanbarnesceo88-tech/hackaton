# 1. Палитра

## 1.1 Что прототип представляет собой структурно

Прежде чем менять цвет, нужно назвать то, что менять **нельзя** — архитектуру.

`:root` (строка 16) задаёт лестницу поверхностей, а не набор цветов. В OKLCH она выглядит так
(вычислено из hex прототипа):

| `--line-faint` | `#1F3A3F` | `0.33 0.034 210.7` | разделитель внутри блока |

| `--text-dim` | `#647A7F` | `0.56 0.027 213.0` | метки, подписи |

| `--accent-strong` | `#22CCD6` | `0.77 0.126 201.4` | акцент активный |

Три вещи здесь важны и переносятся без изменений:

1. **Шаг светлоты ≈ 0.045–0.08 OKLCH.** 0.22 → 0.26 → 0.31 → 0.39. Это достаточно, чтобы
   глаз читал вложенность, и мало, чтобы интерфейс не рассыпался на слои.
2. **Границы — не нейтральные, а на ступень светлее своей поверхности.** `--line` (0.37)
   светлее `--surface` (0.26) ровно настолько, чтобы прочитаться, и темнее `--surface-3`
   (0.39), чтобы не спорить с ней.
3. **Три ступени текста, а не две.** `--text` / `--text-muted` / `--text-dim` — иерархия
   несёт смысл: значение / пояснение / метка поля.

И одна вещь, которая **создаёт всю идентичность BCB** и которую нужно сломать:

> **Вся палитра заперта на одном тоне.** Фон H216.6, поверхность H217.3, линия H210.0,
> вторичный текст H213.5, акцент H200.3. Разброс — 17°. Цветность нейтралей 0.022–0.045,
> то есть это не серые с примесью, а полноценный бирюзовый, просто тёмный.
> Интерфейс выглядит как одна вещь именно поэтому: комната и акцент — один цвет разной силы.

Это и есть точка расхождения. Подробно — в §6, D1.

## 1.2 Решение по акценту

**ПРЕДЛОЖЕНО.** Акцент — `oklch(0.660 0.168 258)` = `#4b91f7`, «кобальт».
Прототип — `#62CCD2` (H200.3). Смещение — **58° по тону**.

Обоснование для инструмента экономики промышленной роботизации, адресованного скептичному финдиректору:

1. **Бирюза занята другой предметной областью.** У BCB циан — это вода, гигиена, клининг;
   он там уместен буквально. Наш продукт считает CapEx, срок окупаемости и NPV. Тот же тон
   унёс бы с собой чужую отраслевую коннотацию.

2. **Аргумент от чисел, а не от вкуса: бирюза слишком близка к «хорошо».** В прототипе
   `--ok` = `#4ADE9B` = H159.6, акцент = H200.3. Между «акцентом» и «положительным
   результатом» — 41°. В ROI-интерфейсе, где зелёный означает «экономия», а акцент означает
   «сюда нажать», эти две роли не должны быть соседями по кругу: пользователь, которому
   показывают его деньги, не должен угадывать, цвет здесь декоративный или смысловой.
   Кобальт H258 отстоит от `--positive` H158 на **100°** и от `--caution` H78 на 180°.
   Семантическая триада (зелёный/янтарный/красный) занимает дугу 25°–158°; акцент вынесен
   за её пределы целиком.

3. **Синий — родной язык финансовой отчётности.** Это не метафора, а привычка аудитории:
   бухгалтерские и аналитические системы, в которых финдиректор проводит рабочий день,
   синие. Акцент, который не нужно объяснять, экономит доверие на другие вещи.

4. **Непрерывность с уже выпущенным брендом.** Текущий `app/globals.css` держит
   `--primary: oklch(0.42 0.17 264)` — платформа задеплоена на robotization-roi.vercel.app с
   этим синим. H258 — это тот же бренд, сдвинутый на 6° и выведенный на максимум цветности,
   достижимой в sRGB на этой светлоте (C 0.168 при L 0.66 — практический потолок для синего).
   Смена облика на тёмный не требует переучивать аудиторию заново.

**Почему не фиолетовый / не янтарный.** Янтарь (H≈78) — это `--caution`; отдать его бренду
значит лишиться предупреждающего состояния или переопределить всю триаду. Лаймовый и зелёный
(H 130–160) конфликтуют с «экономией». Фиолетовый (H≈290–300) свободен и проходит по
контрасту (`oklch(0.66 0.17 290)` = `#937cf1`, 5.08:1 на карточке) — это работающая
запасная опция, но он читается как потребительский финтех, а не как производственный расчёт.

**Различимость от прототипа.** Акцент 58°, нейтрали — 146° (§1.3). Это не перекраска.

# 3. Пространство, радиусы, границы, тени

## 3.1 Шкала отступов

**ИЗВЛЕЧЕНО** (стр. 76): `--sp-1: 4px; --sp-2: 8px; --sp-3: 12px; --sp-4: 16px; --sp-5: 22px; --sp-6: 30px; --sp-7: 44px;`

Это **не** линейная 4pt-сетка. До 16px шаг 4px, дальше прогрессия ×1.36–1.47 (16→22→30→44),
то есть примерно √2. Практический смысл: мелкие внутренние зазоры точны и кратны, крупные
разделители растут геометрически и потому не сливаются друг с другом. Именно это даёт
прототипу его плотность — интерфейс тесный внутри блока и просторный между блоками.

Верхние три ступени в Tailwind не существуют (`p-5` = 20px, не 22; `p-7` = 28px, не 30).

**ПРЕДЛОЖЕНО:** оставить числовую шкалу Tailwind для 4/8/12/16 (`1`/`2`/`3`/`4`) и завести три
именованных шага, которые с ней не конфликтуют:

```
--spacing-lg:  1.375rem;  /* 22px — --sp-5: внутренний отступ вида, зазор между панелями */
--spacing-xl:  1.875rem;  /* 30px — --sp-6: горизонтальный отступ вида, поле документа */
--spacing-2xl: 2.75rem;   /* 44px — --sp-7: нижний отступ вида, пустое состояние */
```

Дают `p-lg`, `gap-xl`, `mb-2xl` и т. д. Переопределять `p-5`/`p-7` нельзя — сломает
существующий код приложения.

Применение в прототипе: `.view { padding: var(--sp-5) var(--sp-6) var(--sp-7) }` (стр. 450) —
асимметрия сверху/с боков/снизу; `.grid { gap: var(--sp-4) }` (стр. 474) — 16px между
карточками; `.panel { padding: var(--sp-4) }` (стр. 494) — 16px внутри панели;
`.tile { padding: var(--sp-4) var(--sp-5) }` (стр. 530) — плитка шире, чем выше.

## 3.4 Тени и модель высоты

**ИЗВЛЕЧЕНО** (стр. 83–84, светлая ветка — стр. 140–141):

```
тёмная:  --shadow-panel: 0 18px 44px rgba(0, 0, 0, 0.42);
         --shadow-pop:   0 26px 70px rgba(0, 0, 0, 0.60);
светлая: --shadow-panel: 0 14px 34px rgba(22, 40, 45, 0.12);
         --shadow-pop:   0 24px 60px rgba(22, 40, 45, 0.22);
```

Два наблюдения, и оба — правило, а не деталь:

1. **Тени не нейтрально-чёрные в светлой теме** — `rgba(22,40,45,…)` — это `--bcb-green-dark`.
   Тень тонирована самым тёмным цветом палитры. **ПРЕДЛОЖЕНО:** тонировать в наш
   `--foreground` светлой темы — `rgba(24, 21, 18, 0.12)` / `rgba(24, 21, 18, 0.22)`.

2. **Внутри потока тени нет вообще.** `.panel`, `.tiles`, `.term-item`, `.rcard`, `.inspector`,
   `.bar`, `.rail` — только граница и ступень светлоты. `--shadow-panel` и `--shadow-pop`
   применяются исключительно к тому, что вышло из потока: `.usermenu`, `.modal`, `.toast`,
   `.asst__fab`, `.asst__bubble`, `.asst__panel`.

> **Правило высоты, которое надо записать и соблюдать:**
> высота внутри страницы выражается **ступенью светлоты поверхности плюс границей**;
> тень появляется только тогда, когда элемент физически перекрывает страницу.
> Три уровня: `card` (0.230) → `muted` (0.278) → `secondary` (0.335); всплывающее —
> `popover` (0.255) **плюс** `--shadow-panel`; модальное — `card` плюс `--shadow-pop`.
> Это заметно строже, чем shadcn по умолчанию, где тень есть у карточки, и это существенная
> часть того, почему прототип выглядит как прибор, а не как набор плиток.

## 5.2 Правила, которые здесь зашиты

1. **Интерактивный отклик — 0.14–0.2s; появление слоя — 0.24–0.28s.** Разница не случайна:
   на отклик кнопки глаз смотрит, поэтому он должен быть быстрее порога заметности; на
   появление окна глаз ещё не навёлся, и ему нужна траектория.

2. **Данные движутся `linear`, интерфейс — `ease`.** `.meter > i` и `.battery__fill` —
   единственные два места с `linear` (стр. 649, 688). Это принципиально: у изменения значения
   не должно быть характера. Замедление в конце читается как «прибывает», а прибывает не
   анимация, а число. **Переносить обязательно** — в ROI-инструменте это и есть главный класс
   анимаций (пересчёт NPV, срока окупаемости, шкал чувствительности).

3. **Появление = сдвиг 8px + прозрачность, ничего больше.** `toast-in`: `translateY(8px)` → 0.
   `bubble-in`: `translateY(8px) scale(0.98)` → norm. Никаких пружин и разворотов.
   Совпадает с уже принятым в приложении переходом шагов мастера
   (`wizard-step-in`: 220ms ease-out, `translateY(8px)`) — то есть система уже согласована.

4. **`prefers-reduced-motion` — полное глушение, не смягчение** (стр. 257–263):
   `animation-duration: 0.001ms !important; animation-iteration-count: 1 !important;
   transition-duration: 0.001ms !important` для `*, *::before, *::after`.
   Плюс адресное отключение анимаций персонажа (стр. 1560).

## 5.3 Предложение

**ПРЕДЛОЖЕНО.** Назвать то, что в прототипе выражено числами:

```
--ease-out:    cubic-bezier(0.22, 1, 0.36, 1);   /* появление слоёв */
--ease-inout:  cubic-bezier(0.65, 0, 0.35, 1);   /* пульсации */
--dur-tap:     140ms;   /* кнопка, вкладка, чип */
--dur-hover:   200ms;   /* карточка, крупная цель */
--dur-enter:   240ms;   /* тост, поповер, модальное */
--dur-value:   400ms;   /* шкала, счётчик — ТОЛЬКО linear */
```

Из продукта уходят как неуместные: `halo`, `pin`, `breathe`, `blink` (принадлежат
2.5D-карте и персонажу). Остаются и получают применение: `pulse` — только для «идёт расчёт»;
`march` — бегущий пунктир как индикатор незавершённого/модельного значения, что напрямую
поддерживает дифференциатор D3.

# 6. Дифференциаторы

Четыре приёма, по которым результат не прочитывается как клон. Первые два обязательны,
остальные два усиливают.

## D1 — Разделённая ось цвета

**Что в прототипе.** Вычислено в §1.1: `--ground` H216.6, `--surface` H217.3, `--surface-2`
H208.7, `--line` H210.0, `--text-muted` H213.5, `--accent` H200.3 — весь интерфейс уложен в
17° тона; цветность нейтралей 0.022–0.045. Комната и акцент — один цвет разной силы. Это и
есть подпись BCB, и она держится не на конкретном hex, а на **совпадении оси**.

**Что делаем.** Ось разводится:

| | Прототип | Предложение | Разница |
|---|---|---|---|
| Тон нейтралей | H 208–217 (бирюзовый) | **H 70** (тёплый графит) | **146°** |
| Цветность нейтралей | C 0.022–0.045 | **C 0.006–0.010** | втрое слабее |
| Тон акцента | H 200.3 | **H 258** | **58°** |
| Отношение акцента к комнате | тот же тон | **противоположная половина круга** | — |

Результат: холодный высокоцветный объект в тёплой почти-нейтральной комнате. Акцент не
«ярче фона» — он **другого рода**, чем фон, и потому не требует яркости, чтобы быть
замеченным. Для инструмента, где акцентом помечается решение (окупаемость, ставка
дисконтирования, кнопка «пересчитать»), это функциональное, а не декоративное свойство.

Приём работает на любом экране и не зависит от того, заметит ли зритель отдельные приёмы
вёрстки. Это главный дифференциатор.

## D2 — Фаска и мерная линейка вместо скобок HUD

**Что в прототипе.** Приборный «тэлл» BCB — `.airbox` (стр. 1203–1209): полностью скруглённый
бокс 10px, поверх которого псевдоэлементами нарисованы **две L-образные скобки 14×14,
толщиной 2px**, акцентным цветом, в противоположных углах (верхний левый и нижний правый),
каждая со скруглением своего угла. Это язык прицела/визира.

**Что делаем.** Скобки убираются полностью. Взамен — два приёма, применяемых **только к
поверхностям, которые несут числа** (карточка KPI, панель графика, панель таблицы); проза,
формы и элементы управления остаются скруглёнными как есть.

**(а) Одна фаска 45°** на нижнем правом углу — 10px срез вместо скругления:

```css
.surface-data-edge {
  border-radius: var(--radius-xl) var(--radius-xl) 0 var(--radius-xl);
  clip-path: polygon(
    0 0, 100% 0,
    100% calc(100% - 10px), calc(100% - 10px) 100%,
    0 100%
  );
}
```

> `clip-path` срезает и границу тоже. Если нужна видимая рамка по фаске — рисовать
> подложкой: обёртка с фоном `--border` и `clip-path`, внутри — блок с фоном `--card`,
> тем же `clip-path` и `margin: 1px`. Это надёжнее, чем `border-image`, и печатается.

**(б) Мерная линейка** — полоса делений 3px по верхней кромке поверхности, шаг 8px,
каждое пятое деление длиннее и светлее. Читается как кромка чертёжной линейки или шкала
штангенциркуля, а не как рамка прицела:

```css
.surface-data-rule::before {
  content: "";
  position: absolute; inset-inline: 0; top: 0; height: 3px;
  background:
    repeating-linear-gradient(to right,
      var(--dim-foreground) 0 1px, transparent 1px 40px),
    repeating-linear-gradient(to right,
      var(--border) 0 1px, transparent 1px 8px);
  opacity: 0.9;
}
```

Почему именно так: скобка обещает наблюдение в реальном времени («объект в прицеле») —
для диспетчерской это правда. Наш продукт ничего не наблюдает, он **измеряет**. Линейка —
честная метафора того же уровня выразительности, и она не совпадает ни одной линией
с прототипом.

## D3 — Незаливаемые данные и штрих как источник числа

**Что в прототипе.** `charts.js`: у `areaLine` под линией — градиентная заливка от
`stop-opacity 0.3` к 0 (стр. 3574–3575), линия 1.8px, последняя точка обведена кружком
r 3.6 с обводкой цветом поверхности (стр. 3579); у `bars` — скруглённые столбцы `rx 3`,
`fill-opacity 0.85` (стр. 3610), значение подписано **над** столбцом (стр. 3611); сетка — сплошные
горизонтали `--line-faint` через всю ширину на каждом делении (стр. 3598–3603, в `areaLine` — стр. 3555–3558).

**Что делаем.**

1. **Заливок нет.** Линия 1.5px, и единственная тяжёлая линия на графике — **базовая ось
   2px** цветом `--border`. Площадь под кривой в инструменте, где ось Y редко начинается с
   нуля, вводит в заблуждение: она рисует «объём», которого в данных нет.
2. **Столбцы прямоугольные** (`rx 0`), без `fill-opacity`. Значение — **внутри** столбца,
   цветом `--card`, если столбец длиннее подписи; иначе снаружи цветом `--muted-foreground`.
   Скругление и полупрозрачность — два способа сказать «это иллюстрация»; в отчёте для
   финдиректора нужно противоположное.
3. **Сетки нет — есть засечки.** Вместо сплошных горизонталей через всю ширину — засечки 6px
   у оси на тех же делениях, что даёт `scale()`. Плюс **одна** штриховая опорная линия
   на пороге решения (NPV = 0, горизонт окупаемости) цветом `--dim-foreground`,
   `stroke-dasharray: 2 4`. Сетка перестаёт быть клеткой и становится шкалой.
4. **Штрих кодирует происхождение числа** — приём, которого у прототипа нет вовсе, и который
   продукт уже заслужил: в репозитории есть `components/provenance-badge.tsx` и
   `scripts/check-sources.ts`, то есть различение «введено пользователем / взято из
   справочника» уже смоделировано. Переносим его **внутрь графики**:
   - сплошной штрих — значение введено пользователем;
   - `stroke-dasharray: 4 3` — модельное значение или отраслевой ориентир;
   - та же штриховка — на границе столбца и на ленте неопределённости вокруг линии.

   Легенда: одна строка «сплошное — ваши данные, штриховое — допущение модели».

Это сильнейший из приёмов с точки зрения аудитории: скептичный финдиректор первым делом
спрашивает не «сколько», а «откуда». График, который отвечает на это **сам, своим
начертанием**, а не сноской, снимает вопрос до того, как он задан. И одновременно
не оставляет ни одной общей детали отрисовки с прототипом.

## D4 — KPI как леджер-лента, а не сетка плиток

**Что в прототипе.** `.tiles` (стр. 521): один обведённый контейнер, скруглённый 16px, внутри
четыре плитки, разделённые вертикалями `--line-faint`, у последней граница снята.

**Что делаем.** Идея «четыре показателя — один объект» сохраняется, рисунок меняется:

- контейнер **без рамки и без скругления**;
- разделители — волосяные линии, которые **выходят за содержимое** в поля (отрицательный
  `margin-inline` на всю ленту, `padding-inline` на ячейках), как графление бухгалтерской
  книги, где линия идёт от края до края;
- сверху и снизу ленты — по одной линии `--border`, между ячейками — `--border-faint`;
- **у одного, решающего показателя** (срок окупаемости) — подчёркивание 2px цветом
  `--primary` под значением; у остальных — ничего.

Последнее — содержательное, а не декоративное отличие. В диспетчерской четыре показателя
равноправны, потому что смотрят за четырьмя разными вещами. В расчёте окупаемости
равноправия нет: есть один ответ и три обстоятельства. Композиция должна это показывать.

1. **`@media print`.** Блок уже принудительно возвращает светлые токены внутри `.dark` —

## Приложение: чего в прототипе нет и что придётся спроектировать с нуля

Прототип — диспетчерская. У него нет и не может быть взято:

- **Мастера/визарда** с шагами и валидацией (есть `.bsteps` — конструктор техкарты,
  стр. 1166–1180: пронумерованный кружок 26px + заголовок 15px + чек-лист; это ближайший
  аналог и годная основа для шага мастера, но не для его навигации и прогресса);
- **Таблицы сравнения сценариев** (есть `.table--week`, стр. 1161, с `white-space: nowrap`
  и горизонтальной прокруткой — механизм переносим, семантика нет);
- **Печатного отчёта** — есть `.docpage` (стр. 1232): подложка `--surface-2`, поле 30px,
  `line-height: 1.6`, центрированная шапка с линией снизу, блок подписей внизу
  (`.docpage__sign`, стр. 1241). Это макет документа на экране, а не стиль печати;
  `@media print` в прототипе отсутствует полностью.
- **Мобильной раскладки** — единственная точка перелома 1280px, ниже неё поведение
  не определено.
