# Платформа оценки роботизации

Веб-платформа подбора роботизированных решений с расчётом экономического эффекта и
визуализацией работы роботов на объекте — решение задачи ФЦ БАС («Лидеры цифровой
трансформации», 2026).

Пользователь выбирает объект, вводит или загружает его параметры, получает объяснимую
подборку решений из каталога, сравнивает сценарии «Как есть», «Покупка» и «Услуга (RaaS)» по
CAPEX, OPEX, эффекту, окупаемости, ROI, NPV и TCO, проверяет расчёт имитацией работы роботов на
2D-схеме и выгружает отчёт. Всё — в рублях, на данных организатора, с источником у каждого
числа.

**Текущий срез, 18.10.2026:** изменения находятся в локальном рабочем дереве, без commit/push и внешней публикации. Прежний стенд https://hackaton-ten-delta.vercel.app не объявляется обновлённым до этой версии. Проверяемая локальная production-сборка — `http://localhost:3081`, дополнительный 3D-просмотр — `/warehouse-3d.html` на том же сервере. Для стороннего запуска используйте инструкции ниже; эти адреса не заменяют передачу исходников.

Для владельца собирается локальный ZIP финальных исходников с SHA-manifest: без `.env`, `.git`, `node_modules` и тестовых секретов. Это пакет передачи, а не внешняя публикация. Имя, размер и SHA самого ZIP записываются рядом с архивом в `delivery-summary.json`; внутренний manifest содержит SHA включённых исходников. Пакет предкоммитного этапа хранится вне checkout: `../research/alfa-audit/precommit-20261018/delivery/`.

- **Демонстрационный объект — склад** из датасета организатора: полная модель (подбор,
  экономика, сценарии, имитация). Аэропорт и медучреждение — выбор, параметры и доступные
  решения (ТЗ §5.5).
- **Модели:** экономика `tz-1.0.4`; базовая 2D-имитация `sim-1.1.0`; дополнительная пространственная проверка `warehouse-demo-incidents-1.4.0` / `traffic-1.3.0`. Это разные контуры проверки. Их результат относится к обозначенному входу, версии и seed; положительная экономика не подтверждает выполнение нагрузки. Точная версия и SHA сдаточной сборки фиксируются в release-manifest после финального прогона.
- **Дополнительные расходы эксплуатации и комплектация** задаются явно: новый штат, доплата существующему сотруднику либо диспетчеризация интегратором; ПО/ремонт/зарядки, уже включённые в цену, повторно не оплачиваются. Без новых настроек прежняя арифметика сохраняется. Сравнение до трёх моделей и покупки/RaaS использует одну нагрузку, план и трудовые допущения; физическая проверка каждого состава показывается отдельно. [Числа и границы примеров](./docs/ECONOMICS-2026-10-18.md).
- **Что реализовано полностью, частично и как прототип** — [docs/LIMITATIONS.md](./docs/LIMITATIONS.md).
- **Предкоммитная проверка:** исправлены блокировка сервера расчётами, лимит сохранения больших проектов и выпуск битого 3D-HTML; [разбор с доказательствами и ограничениями](./docs/PRECOMMIT-REVIEW-2026-10-18.md).
- **Демо-числа** печатает текущая сборка: `npx tsx scripts/print-demo-numbers.ts`, файл — [docs/submission/demo-numbers.md](./docs/submission/demo-numbers.md). Пока он помечен историческим, прежние числа нельзя использовать в питче. Для новых пространственных сценариев сохраняются отдельные воспроизводимые входы и результаты. Результат — предварительная оценка, требующая проверки при обследовании объекта.
- **Сдача и требования:** [актуальная трассировка](./docs/TZ-COMPLIANCE.md), [повторный аудит исходного ТЗ](./docs/TZ-RECHECK-2026-10-17.md) и [статус сдаточных материалов](./docs/submission/README.md). Нагрузка 50 пользователей / 300 действий чтения измерена на предыдущем этапе; железо, cache и границы приведены в плане §0.15. Новый экономический пакет проверен отдельно и не выдаётся за повторный нагрузочный прогон.

## Путь жюри (ТЗ §5.4) — 8 шагов

1. **Вход** демо-пользователем `demo@demo.local` / `demo-user-2026` → «Мои проекты».
2. **Новый проект** → «Склад» → «Демо-данные организатора» (или «Загрузить Excel/CSV по
   шаблону») → «Создать проект».
3. **Шаг 2 · Параметры** — поля с единицами, примерами, диапазонами и источником каждого
   значения; правка → «Пересчитать».
4. **Шаг 3 · Подбор** — решения с причинами включения и исключения, ограничениями,
   недостающими данными и баллом из пяти факторов.
5. **Шаг 4 · Сравнение** и **Шаг 5 · Экономика** — характеристики решений, состав
   оборудования, CAPEX и OPEX по статьям с формулами и источниками, «Как посчитано».
6. **Шаг 6 · Сценарии** — «Как есть», покупка и услуга в одной таблице, чувствительность,
   риски, вывод с интерпретацией.
7. **Шаг 7 · Имитация** — выбрать тот же сценарий, показать требуемый/достигнутый поток и ограничения, запустить схему, сохранить PNG. Дополнительно открыть точную проверку в 3D; новый состав передаётся в отдельный финансовый сценарий после повторного расчёта и явных годовых допущений.
8. **Шаг 8 · Результат и план внедрения** — выбранный сценарий, отдельный небольшой пилот с целями/сметой/источниками/неизвестными, «Сохранить проект», «Отчёт (PDF)», «Excel», «CSV».

Запасные пути: гостевой `/demo` без входа (весь путь без сохранения) и готовый проект
«Склад организатора (демо)» у демо-пользователя. Аэропорт и медучреждение —
`/demo?facility=airport` и `/demo?facility=medical`. Подробно — [docs/USER-GUIDE.md](./docs/USER-GUIDE.md).

## Запуск

### A. Docker одной командой (основной путь, проверяется в CI)

Нужны Docker с Compose v2 и сеть на время первой сборки (`npm ci` и шрифты скачиваются при
сборке).

```bash
git clone <репозиторий> && cd <каталог>
docker compose up --build
```

Первая сборка — ориентировочно 5–10 минут. Затем откройте http://localhost:3000. Compose
поднимает базу, выполняет миграции и сев (каталог, нормативы, демо-аккаунты, демо-проект) и
запускает приложение; проверка — `curl http://localhost:3000/api/health`. Порты меняются
переменными `APP_PORT` и `DB_PORT`, чистый старт — `docker compose down -v`.

### B. Локально без Docker

Нужны Node.js 20.9+ и PostgreSQL 16 (по умолчанию `localhost:5433`, как в `.env.example`).

```bash
npm ci
cp .env.example .env          # впишите AUTH_SECRET: openssl rand -base64 32
npx prisma migrate deploy
npm run db:seed
npm run build
npm start                     # http://localhost:3000
```

Если изменялись исходники дополнительной пространственной сцены, перед финальным `npm run build` пересоберите её автономные HTML:

```bash
node experiments/warehouse-3d/build.mjs
```

Команда обновляет `public/warehouse-3d.html` и `public/cleaning-3d.html`. Основной SVG-путь и эти дополнительные WebGL-артефакты проверяются отдельно; номера версий в них должны совпадать с исходниками финальной сборки.

Без Docker тот же путь на временной базе проверяет `npm run check:fresh`. Подробно, включая
Vercel с новой базой Neon, — [docs/DEPLOY-QUICKSTART.md](./docs/DEPLOY-QUICKSTART.md).

## Демо-аккаунты

| Роль | Почта | Пароль по умолчанию | Переменная |
|---|---|---|---|
| Пользователь | `demo@demo.local` | `demo-user-2026` | `DEMO_USER_PASSWORD` |
| Администратор | `admin@demo.local` | `demo-admin-2026` | `DEMO_ADMIN_PASSWORD` |

Аккаунты создаёт сев. Пароли меняются переменными окружения при севе; на стенде, доступном
извне, задайте свои и передайте жюри отдельно. Лимит входа: для `@demo.local` — 100 попыток за
15 минут на пару «почта + адрес», и 50 попыток за 15 минут на один адрес — общий для всех, кто
входит из одной сети.

## Данные организатора

Файлы организатора (xlsx, csv, docx) в репозиторий не входят: из них перенесены только нужные
поля со ссылкой на место в файле. Сгенерированные модули лежат в `lib/data/organizer/`.
Перегенерировать их из JSON-выгрузок:

```bash
ORGANIZER_DATA_DIR=<папка с выгрузками> npm run gen:organizer
npm run db:seed
```

Какие файлы нужны и как выбирается значение при расхождении источников —
[docs/data-provenance.md](./docs/data-provenance.md).

## Тесты

```bash
npx vitest run --project unit < /dev/null   # чистые модули
npx vitest run --project db < /dev/null     # тесты на настоящем Postgres (после миграций и сева)
npm run test:e2e                            # Playwright: собирает и запускает приложение сам
npx tsx scripts/print-demo-numbers.ts       # демо-числа на данных БД
```

Перед первым `test:e2e` — `npx playwright install chromium`. CI (`.github/workflows/ci.yml`)
на каждый push выполняет миграции, сев, lint, сборку, Vitest и e2e, а отдельная задача
`docker` — `docker compose up --build` с проверкой `/api/health`, `/` и `/demo`. Старые цифры CI коммита `b112b35` относятся к историческому срезу, а не текущему рабочему дереву. Свежие локальные проверки, их версии и точная область приёмки записываются в итоговый manifest и `research/alfa-audit/`; выполнение юнит-тестов само по себе не подтверждает нагрузку 50 пользователей и промышленную безопасность.
